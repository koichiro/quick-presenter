実際の動作を見る

ノートが、そのままナレーションに。

PDFに埋め込まれた発表者ノートを、ローカルの音声エンジンで読み上げます。音声が終わるたびにページが進む、発表者ビューの動きをご覧ください。

  1. 01

    ノートを取得

    外部の実行スクリプトが、Marpで作成したPDFの発表者ノートをqpで取得します。

  2. 02

    TTSで読み上げ

    ローカルの音声合成（Kokoro）でノートを音声に変換し、最後まで再生されるのを待ちます。

  3. 03

    次のページへ

    CLIでページを進めると、現在のスライド、ノート、次ページのプレビューも切り替わります。

このデモはノートをそのまま読み上げます。Kokoroは任意で導入する外部エンジンです。Quick PresenterはPDFの情報取得と再生操作を担います。

デモを試す↗
読み上げ原文と日本語訳を見る

動画の音声は英語です。各スライドの原文と日本語訳を掲載しています。

スライド 1. Welcome to this short Quick Presenter demo. Each slide has a speaker note containing the words you are hearing. The demo reads those notes aloud, waits for the speech to finish, and then moves to the next slide.

Quick Presenterの短いデモへようこそ。各スライドには、いま聞こえている文章を発表者ノートとして埋め込んであります。このデモはそのノートを読み上げ、音声が終わるのを待ってから次のスライドへ進みます。

スライド 2. The audience sees only the key ideas on this slide. The full explanation lives in the speaker notes embedded in the PDF. This demo reads that explanation word for word. It does not invent an explanation or read the bullet points instead.

聴衆に見えるのは、このスライドの要点だけです。詳しい説明はPDFに埋め込まれた発表者ノートにあります。このデモは、その説明を一語ずつそのまま読み上げます。説明を創作したり、代わりに箇条書きを読み上げたりはしません。

スライド 3. Notice that this slide stays on screen while the narration is playing. Only after the speech finishes does the demo ask Quick Presenter to move forward. If speech playback fails, the demo stops without sending a page change. Keep presentation control exclusive while the demo runs.

読み上げ中、このスライドが画面に表示されたままであることに注目してください。音声が終わってから、デモはQuick Presenterに次のページへの移動を指示します。音声再生が失敗した場合、ページ移動を送信せずに停止します。デモ実行中は、ほかの操作でプレゼンを動かさないでください。

スライド 4. That is the end of the demo. The presentation will stay on this final slide. To make your own version, edit the slide text and the speaker notes in the Markdown source, then export a new PDF with Marp's PDF notes option enabled. Thank you for listening.

デモはこれで終わりです。プレゼンは最後のスライドで止まります。ご自分の資料にするには、Markdownのスライド本文と発表者ノートを編集し、MarpのPDFノート出力オプションを有効にして新しいPDFを書き出してください。ご視聴ありがとうございました。

2.0の新機能 · 安定した自動化インターフェース

プレゼンの情報を、ツールにも。

qpCLIで、発表中のPDFの情報をスクリプトやAIエージェントから取得できます。資料に基づく文脈と明確な再生操作を組み合わせて、自分のワークフローを作れます。

取得

エージェントに文脈を渡す。

現在と次のスライド本文、発表者ノート、プレゼンの状態をJSONで取得。PDFの情報をもとに、エージェントに説明を生成させられます。

qp context --full --json
操作

プレゼンを操作する。

PDFを開く、ページを移動する、投影画面を黒くする。文章の生成や読み上げには、お好みのツールを組み合わせられます。

qp next --json
監視

変化を追いかける。

プレゼンの変化を、1行ごとのJSONとして受け取れます。描画やノートの準備状況は、状態を問い合わせて確認できます。

qp watch --json

お好みのエージェントと連携

生成・読み上げは自由に。
再生は確実に。

ローカルモデル、クラウドサービス、決まった処理を行うスクリプト。ナレーションと音声は外部エージェントが、PDFとプレゼンの状態はQuick Presenterが担当します。

付属のPythonサンプルは準備状況を確認し、音声の完了を待ってからページを進めます。処理が失敗した場合は、次ページへ進む前に停止します。

CLIリファレンスを見る↗

安定した仕様。Control Protocol v1、JSON形式の応答、種類別のエラー、公開された終了コードで、自動化のためのインターフェースを提供します。

配布形式を選ぶ。CLI操作はmacOSのDeveloper ID / DMG版、Windows Store版、Linux版で利用できます。v2.0.0のMac App Store版はCLI操作の対象外です。

発表を支える機能

自動化しても、状況はひと目で。

発表者ウィンドウ

発表に必要な情報を、ひとつに。

現在のスライド、次ページのプレビュー、発表者ノート、タイマー、時計、ページ番号をひとつのウィンドウにまとめています。

投影用の画面

聴衆には、スライドだけを。

投影用ウィンドウにはスライドだけを表示。発表者向けの情報は手元のウィンドウにまとめます。

PDFをそのまま再生

書き出した資料を、そのまま発表。

PDFを発表内容の基準にし、本番の操作を複雑にする編集機能を持たせず、再生に専念します。

資料作成から発表まで

作成ツールは自由。発表にはPDFを。

資料の作成や編集は、使い慣れたツールで。完成したスライドをPDFに書き出して、Quick Presenterで発表できます。

Keynote

完成したスライドをPDFに書き出して発表。

 PowerPoint

作成ファイルではなく、書き出したPDFを再生。

 Google Slides

用意したプレゼン資料をPDFでダウンロード。

 Marp

PDFの発表者ノートに対応する、OSSのMarkdownスライド作成ツール。

 LaTeX Beamer

学術・技術発表向けPDFを作成する、OSSのLaTeXクラス。

対応する入力形式は、各作成ツールのプロジェクトファイルではなく、書き出したPDFです。

再生に専念する設計

本番に必要な機能に、集中。

PDF

プレゼン資料の入力形式はPDFだけ。

編集なし

再生中のスライド編集・作成・デザイン機能はありません。

安定性

描画、ページ移動、問題発生時の回復を優先します。

オープンソース

開かれた開発で、安心できる発表を。

ソースコード、リリースノート、配布に関する文書、課題管理を公開し、OSSのデスクトップアプリとして開発しています。

ソースコード 問題を報告

開発を支援する

これからのプレゼンツールを、一緒に。

安定したPDF再生を軸に、CLIでスクリプトやエージェントとの連携を広げています。開発への支援は、各OSで安心して使える再生体験につながります。

ソースコードを公開したまま開発を続けるため、アプリストアでの購入を通じた支援を予定しています。
